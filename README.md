# decaf377-go

Go decaf377 primitives and verifier compatibility tests.

The module implements the Orbis SHA-512 FROST wire format. Penumbra `decaf377-rdsa` remains a separate API
surface.

## Packages

- `decaf377`: native point encoding/decoding, quotient equivalence, scalar
  handling, point addition, and scalar multiplication.
- `gnark`: reusable decaf377 gnark gadgets and native helpers for circuit
  tests.
- `orbisfrost`: verifier for the current Orbis SHA-512 FROST `(R, z)` wire
  format.
- `rdsa`: verifier for Penumbra-compatible `decaf377-rdsa` SpendAuth
  signatures.

## Verification

Orbis FROST challenges are hashed with SHA-512 before reduction into the
Decaf377 scalar field. Callers using `ScalarFromUniformBytes` for hash-to-scalar
FROST material should provide 64 bytes of input so reduction bias is negligible.

Run:

```sh
go test ./...
```

The Orbis interop test consumes `testdata/orbis_vectors.json`, generated by the
neighboring `orbis-rs` checkout:

```sh
cd ../orbis-rs
ORBIS_VECTOR_OUT=../decaf377-go/testdata/orbis_vectors.json \
  cargo test --no-default-features --features decaf377 -p crypto \
  generate_orbis_frost_interop_vectors -- --nocapture
```

## Native arithmetic security boundary

`ScalarMul` accepts a fixed-width little-endian `Scalar` and consumes all 256
bits without reduction or truncation. `Point` retains fixed-width canonical
coordinates. Multiplication, addition, affine normalization, scalar reduction,
and `Encode` use `filippo.io/bigmod` arithmetic and constant-time selections.
The guarantee concerns valid inputs and secret-independent control flow and
memory access; it is not a formal proof of compiled code or power/EM resistance.

Use `Point.AffineBytes`, `PointFromAffineBytes`, and `CompressToFieldBytes` to
keep secret values at fixed width. `NewPoint` imports **public** `big.Int`
coordinates. `CompressToField` exports a `big.Int` and can reveal the encoded
result's size; use it only when that result may be disclosed. `Decode` and the
`gnark` native helpers process public inputs with variable-time arithmetic.
Circuit constraints do not establish a constant-time witness generator/prover.

Native secret multiplication uses the root package directly:

```go
var scalar decaf377.Scalar // Fill all 32 little-endian bytes from the secret source.
base, err := decaf377.Generator()
if err != nil { return err }
point, err := decaf377.ScalarMul(base, scalar)
if err != nil { return err }
encoded, err := decaf377.CompressToFieldBytes(point)
```

Integer widths such as 128 and 251 bits are caller validation requirements;
`ScalarMul` also supports full 256-bit integers. It never silently masks high
bits. Canonical signature scalars must use `ScalarFromCanonicalBytes`.

Run `go test -run '^$' -bench BenchmarkScalarMul -count=5` for a diagnostic
comparison of zero, one, and dense scalars. Timing measurements are regression
evidence, not proof of constant-time execution. The independent affine oracle
and field arithmetic tests check numerical correctness and encoding parity.
